HTTP run API

Trigger a headless run from outside Slack — Make.com, a cron job, a script — and get the answer back by polling or a webhook. Authenticated with a token you generate under Settings → HTTP run API.

Overview

Each request starts a real gated run. With no channel it runs in a dedicated headless api folder and you read the result back; with a channel it posts as a normal thread in that Slack channel and stays resumable there.

Authentication

Send the token you generated in Settings as either an X-API-Key header or an Authorization: Bearer header. The token is scoped to /api/runs only — it is not a general admin credential and can't read settings, tokens, or the filesystem browser. A logged-in admin session cookie also works from the browser.

POST /api/runs — start a run

Provide a message (and/or a file). The response returns immediately with a jobId; the run itself proceeds in the background.

FieldTypeNotes
messagestringThe prompt. Required unless a file is supplied.
channelstringOptional. Slack channel id, folder slug, or channel name. Omit → headless api folder.
authorstringOptional attribution label (≤64 chars). Defaults to api.
fileobject/stringInline attachment: { name, dataBase64 } (or a raw base64 string). ≤25 MB.
fileUrlstringhttp(s) URL the daemon downloads into the run's uploads/. ≤25 MB.
fileNamestringOverride the saved filename (with fileUrl/inline).
webhookstringhttp(s) URL POSTed once the run finishes (completed or failed).
enginestringPer-run override: claude or codex.
model / effortstringPer-run model / reasoning-effort override.
modestringCapability profile: read, worker, auto, full, lean (aliases bash→worker, admin→full).
idempotencyKeystringAny unique-per-request string. A repeat POST with the same key within 15 min returns the original job instead of starting a second run.

Responses: 202 a fresh run started · 200 an idempotent hit (reused:true) · 400 validation error · 429 too many runs in flight (max 25). 401 if the token is missing or wrong.

Poll the statusUrl from the start response. status is one of running, completed, failed, stopped, interrupted. The answer text is in result once completed.

GET /api/runs — list recent runs

Newest first. Optional ?status= filter and ?limit= (default 50, max 200). Returns { ok, jobs: [ … ] } with the same shape as a single run.

POST /api/runs/:id/stop — stop a run

Aborts an in-flight run. 202 with status:"stopping"; 409 if it's already finished, 404 if unknown. Whatever it cost so far is still billed.

Completion webhook

If you pass a webhook, the daemon POSTs this JSON once the run settles (10 s timeout). Better than polling — let the automation resume on delivery.

Make.com quick start

Use an HTTP → Make a request module:

URLhttps://your-gateway/api/runs
MethodPOST
HeaderX-API-Key: <your token>
BodyJSON — message (required), optional channel, webhook, and idempotencyKey set to the Make execution id.

Point the webhook at a Make custom-webhook trigger so the scenario continues when the run finishes; setting idempotencyKey to {{execution.id}} means a scenario retry never fires the run twice.

Make.com → Slack message trigger

Use this alternative when the automation must post a visible Slack message that triggers the gateway bot. The Make connection below posts as the Integromat bot; its app/bot identity must be trusted, and its Slack bot user must be approved like any other author.

Bot member IDyour bot's member ID (shown here once Slack is connected) — save <@BOT_MEMBER_ID> at the start of mapper.text.
Make bot userthe member your Make Slack connection posts as (shown on its messages) — must be approved under Users.
Trusted identityAllow the Integromat app A0X0JM3SB or bot B059F7J9QR4 under Settings → Trusted bot apps.
Channel accessBoth the gateway bot and the Make app must be members of the destination channel.
Message formatmrkdwn: true, parse: false; link_names is not required for an explicit member-ID mention.
Thread targetMap the root timestamp: {{ifempty(62.thread_ts; 62.ts)}}. Replace 62 with the source module number in your scenario.

Important: verify the mention is present in the saved/exported mapper.text, not only visible in Make's editor. A trusted bot without the saved mention is intentionally ignored.

Runtime changes

Container runtime

Every channel's engine processes run inside its own long-lived Linux container — separate HOME, separate CLI logins, its own process namespace, and none of the host's files reachable beyond the channel's own folders. This is the only runtime: the daemon needs podman or docker on this machine plus a built image (npm run build:image). Admin-mode channels run in their container too; the permission bypass applies inside it, never on the host.
